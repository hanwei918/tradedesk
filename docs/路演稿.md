# 3 分钟路演稿

配合 `docs/pitch/slides.html` 使用，共 13 页，键盘 ← → 翻页；导出版是 `docs/pitch/TradeDesk-路演.pdf`。每页标题就是这一页的结论，照着标题讲不会跑题。
**主线只有一句：TradeDesk 不帮工厂写文案，帮工厂在发出前查。** 生成谁都能做（通用 AI、GitHub 上的 skill），我们做的是发出前那道关。
想现场操作时，第 7、8 页可以切到浏览器；来不及操作就点右上角“自动演示”，12 步带字幕约 90 秒（Esc 退出）。

---

**【第 1 页 · 0:00–0:07】封面**

> 各位评委好，我们是 TradeDesk，给宁波中小外贸工厂用的发出前合规核对工具。

**【第 2 页 · 0:07–0:27】执行摘要**

> 一句话：我们不帮工厂写文案，帮工厂在发出前查。
> 同样 8 条外贸询盘：通用 AI 只看询盘，8 条回复都带红色问题，替工厂声称有 UL 认证、按低于起订量报价。公平地说，手动贴上工厂资料后它也是 0 红，但还有 20 处要人工确认，而且每次都得业务员自己找资料、贴资料。TradeDesk 自动带上资料，改一轮后 3 条可以直接发，每条提示都有出处。

**【第 3 页 · 0:27–0:45】切入点：为什么是合规**

> 做外贸，合规是守住利润的底线。看这条美国询盘（虚构）：要 UL、要 BPA free、FOB 空运、20 天到货、货到 60 天付款。工厂没有 UL、没测过 BPA，FOB 不走空运，20 天做不出，60 天账期收不回钱。回一句 "no problem"，五个坑全踩。

**【第 4 页 · 0:45–1:02】合规内核（亮点）**

> 数字和硬事实交给代码，语义判断交给模型。模型提出的问题必须带规则编号、原文里真有那句话，否则代码丢弃，模型编不出规则来。审核这一步失败，结果绝不显示绿色。

**【第 5 页 · 1:02–1:17】合规效果**

> 同一套检查测四组：通用 AI 8 条全红；贴上资料 0 红、20 处待确认；TradeDesk 改一轮后 8 处待确认、3 条可直接发。第一份盲测集首次精确率 97.1%，第二份 92.3%；红队编造的 5 条提示全部拦下。

**【第 6 页 · 1:17–1:30】定位：和现有做法比**

> 生成谁都能做，GitHub 上随便一个 skill 就能写 Listing。但 skill 写出来的 "UL Listed" 你敢发吗？我们不和它们抢写作，别的工具写的文案贴进来一样能查：每条问题告诉你依据是哪条规则、哪个资料字段。

**【第 7 页 · 1:30–1:40】同一道关**（时间紧可以一句带过）

> 询盘回复、上架文案、看板，都过同一道关：一张资料卡加 61 条带出处的规则。

**【第 8 页 · 1:40–1:58】工作流 A 询盘回复**（可切到浏览器“询盘回复”页现场跑）

> 回复如实写明没有 UL、只报海运、交期 35 天；校验又发现集装箱货用 FCA 更合适，依据是 ICC 原文。业务员说一句“按风险提示全部修改”，第 2 轮变绿。

**【第 9 页 · 1:58–2:08】上架也过同一道关**

> 回完询盘一键带到上架，Amazon、TikTok 等 11 个平台可选；重点不是生成，是每个平台的文案都按平台规则和资料卡查一遍，看板一屏看清哪些能上。

**【第 10 页 · 2:08–2:18】平台配置与调用**

> 6 个智能体按工作流编排，配置在“智能体配置”页能看、能导出。现场走赛事 Tokenhub 的 gpt-5.5，一次询盘回复 3 次调用、22 秒；新询盘可以在“开摊自检”里当场实时跑一遍。

**【第 11 页 · 2:18–2:35】商业价值**

> 替换掉的是三块：业务员写回复的时间、外包翻译、上架前的人工自查。每条询盘的模型费约 0.24 美元，这是模型成本，不是节省金额。人工省多少我们现场计时：在“降本测算 → 现场实测”里记一次人工、一次用 TradeDesk，测到几次就标几次。

**【第 12 页 · 2:35–2:52】可复制与功能取舍**

> 换工厂、换品类只写一张资料卡（第二家示例工厂的保温杯已经跑通）。我们故意不做 AI 生成主图、不自动发送、不爬付费数据，因为那样会违规或替商家乱承诺。

**【第 13 页 · 2:52–3:00】收尾**

> 让每一句对外承诺都有依据。我们是 TradeDesk，谢谢。

## 提问准备

| 可能的问题 | 回答要点 |
|---|---|
| 收件箱的分数怎么算？ | 公开公式：50 分起，每个正面信号 +8、负面信号 −8、硬冲突 −6、待确认 −3，再加数量分。演示里酒店集团 3,200 台的询盘 100 分，"只要目录"的 26 分，每一项都挂询盘原文 |
| 能省多少钱？ | 打开“评测与对照 → 降本测算”：模型费用是实测（每条询盘约 0.24 美元，每个产品的上架文案约 0.14 美元），人工用时、时薪、外包单价是假设，请对方填自己的数，页面写出每一步算式。人工节省没有实测，要试用验证 |
| 每条询盘要花多少钱？ | 按 Claude 官方价（输入 4 美元、输出 20 美元每百万 token）和赛前录制时的实际用量算：第 1 轮 3 次调用，8 条询盘 0.087–0.150 美元，中位数 0.135；加改一轮中位数 0.236 美元。现场换成 Tokenhub 的模型，价格另算。能省多少人工时间我们没有测过，不报数字 |
| 数据从哪来？合规吗？ | 演示用的工厂、产品、询盘、主图全部虚构。61 条规则摘自 Amazon、FTC、EUR-Lex、日本经济产业省、欧亚经济委员会、尼日利亚标准组织、ICC、墨西哥经济部等公开页面，每条附原文摘录、链接和抓取日期，没有爬取付费数据。真实询盘先脱敏、经对方同意才用；key 只存在本机 |
| 召回率是多少？ | 两份盲测集首次运行召回率 94.4% / 82.8%，精确率 97.1% / 92.3% |
| 知识库会过时吗？ | 每条规则都有抓取日期和链接。Amazon 标题上限就是例子：网上普遍写 200 字符，官方页面现在写的是 75。规则更新只需要改一个 JSON 文件 |
| AI 会不会漏报？ | 会。所以数字、认证、像素这些硬性事实交给代码检查，不靠模型；模型只负责语义和看图判断，而且不允许它编造依据 |
| 为什么不直接用 AI 生成产品图？ | 生成的图放上 Amazon 本身就违反"必须是真实照片"的要求，我们的示例图就被判了红。我们的做法是先把工厂已有的实拍图检查合规 |
| 数据是真实的吗？ | 演示用的工厂、产品、询盘、主图都是虚构的，页面上写明了。规则摘录来自真实的公开页面 |
| 和直接用 ChatGPT 有什么区别？ | 评测页有对照实验：直接问通用 AI，8 条回复 8 条带红色问题。但附上工厂资料后它也是 0 条红，这一点我们照实写了。区别在于：TradeDesk 每次自动带上资料、需人工确认的从 20 条降到 8 条、每条提示都有出处，而且有代码规则兜底 |
| 对照实验公平吗？ | 四组用同一个模型（claude-opus-5-5）、同一套代码规则和同一个审核员检查；通用 AI 组的提问原文公开在页面上，每条回复都能点开看全文和依据。检查器是我们自己写的，它本身准不准，看两份盲测集 |
| 模型会不会编造依据混过去？ | 红队测试页可以现场试：自己编一条规则编号或原文，点"注入并检查"，代码会说明为什么拦下 |
| 盲测成绩是怎么来的？ | 两份各 30 条，分别由没看过检查代码的人按规则说明写；第一次运行的结果在修改前冻结保存，评测页上能看到每一条用例。只测代码规则层，可以完全复现。对照实验里又发现两处检查器误判（"以后可以谈赊账"被判成接受赊账；把表情符号这类语气问题判成红），都已修复并加了测试 |
| 还有什么做不到？ | 不带 MOQ 关键词的起订量承诺（比如 "we can start at 500 pcs"）代码规则抓不到，评测页写明了这是已知局限 |
| 现场用的什么模型？ | 赛事 Tokenhub 发的是 Codex 周卡，只有 GPT 系列，现场用 gpt-5.5，走 OpenAI 兼容接口；10-30 实测一次询盘回复 3 次调用共 22 秒。仓库里的回放缓存和对照实验是赛前用 claude-opus-5-5 录的，断网时用回放演示 |
| 下一步做什么？ | 接阿里国际站的询盘接口；补充更多品类的认证和主图要求；找宁波工厂做两周试用 |
