# 演示说明

## 用到的设备、平台、模型和数据

| 项 | 作用 |
|---|---|
| 一台笔记本（macOS 或 Windows，装 Python 3.9+） | 运行本地服务 `app/server.py`，浏览器打开界面 |
| 大模型接口（OpenAI 兼容或 Claude；仓库里的回放缓存用 `claude-opus-5-5` 录制，现场可换赛事 Tokenhub `api.tokenhubcloud.net`，两种接口都支持） | 询盘理解、回复生成、Listing 生成、合规审核 |
| 规则知识库 `app/kb/rules.json` | 每条规则带原文摘录和来源链接；生成时注入规则摘要，审核时作为唯一依据 |
| 产品资料卡 `app/data/products.json` | 价格、MOQ、交期、认证、材料检测情况；代码用它核对数字和认证 |
| 示例询盘 `app/data/inquiries.json` | 8 条固定演示输入（虚构），保证现场可重复 |
| 缓存 `app/cache/` | 回放模式的模型答案，断网时用 |

## 演示前准备（开场前 10 分钟）

1. 打开终端，进入 `app/` 目录，运行 `python3 -m unittest discover -s tests`，确认测试全部通过。
2. 决定模式：
   - 网络和模型都正常：运行 `python3 server.py`，状态栏应显示"实时模式"。
   - 网络不稳：运行 `TRADEDESK_MODE=replay python3 server.py`，状态栏应显示"回放模式"。
3. 浏览器打开 http://127.0.0.1:8765 ，左下角应显示模型名和"回放模式"或"实时调用"。
4. 看板要有演示数据：运行 `python3 tools/record_demo.py`（回放缓存齐全时不会产生费用），它会重置看板，并填好 4 个产品和 4 张主图的结果。
5. 把"调用日志"页清空，让评委只看到当场的调用：停掉服务，删除 `app/logs/calls.jsonl`，再重新启动。
6. 浏览器缩放调到 125%，方便后排观众看清。

## 演示步骤（对应路演稿第 3–7 页）

1. **工作流 A**：在"询盘回复"页选中"美国买家 · 英文 · 要空运 FOB"卡片，点"理解 → 生成 → 校验"。输入栏会自动收起。
   - 往下翻到"询盘分析"，指给评委看"和工厂资料对不上"的 5 条（UL、BPA、付款、交期、运输方式），每条都带询盘原文。
   - 右侧风险卡：依据是 INC-02 的 ICC 原文和链接。点正文里的高亮，会跳到对应的风险卡。
   - 点底部快捷建议"按风险提示全部修改"，再点"改出第 2 轮"。右上角出现"第 2 轮"，风险变绿；切到"与上一轮对比"标签页，能看到新增的那句话。
2. **工作流 C · 商品看板**：切到"商品看板"。
   - 讲清楚这一页是"运营每天的第一页"：4 个产品 × 主图 / Amazon / TikTok，每格一个状态。
   - 点"批量生成全部 Listing"，看进度条和格子逐个刷新。
   - 点热水壶的"主图"格子：左边是图和 4 个像素指标，右边是 5 条红。指出"看到：…"那一行，说明模型必须写出它看到了什么。
   - 指出底部"标记已上架"按钮是灰的：红色时不允许标记。
   - 选示例图 `KET-17S_main.png`，点"检查这张图"：只剩 1 条红（不是实拍照片），其他像素指标都通过。
   - 点"导出 CSV"。
3. **工作流 B**：切到"多平台上架"，点"生成 → 校验"。左边是 Amazon 商品页预览（标题旁显示字符数 / 75），右边是 TikTok 手机预览和分镜脚本，各自显示风险等级。
4. **文案体检**（展示代码规则拦截）：切到"文案体检"，点"检查"。示例标题会被标出 6 红 1 黄，每条都带依据。
5. **出处守卫**：风险面板底部的"出处守卫"说明了模型的每条提示都核对过规则编号和原文；如果有被丢弃的，会显示"已丢弃 N 条模型提示"，可以展开看原文。
6. **对照实验**：切到"评测与对照"，默认就是"对照实验"标签页。
   - 四张卡片：直接用通用 AI 8/8 条不能发；附上工厂资料 0/8；TradeDesk 第 1 轮 0/8；改一轮后 0/8，且黄色最少。
   - 一定要照实讲下面那句"怎么读这个结果"：附上资料后通用 AI 也是 0 条红，差距主要来自资料；TradeDesk 的价值是自动带资料、黄色更少、条条有出处。
   - 点"直接用通用 AI"那一列的任意格子，能看到回复全文：带方括号的模板选项、声称有 UL/ETL 认证、承诺免费样品。
7. **红队测试**：切到"红队测试"标签页，点"注入并检查"。6 条注入的模型提示，5 条编造的被拦下，每条写明原因（编造的规则编号、原文里没有、规则不适用于这个平台……），1 条真实的保留。可以请评委自己改 JSON 再试。
8. **调用日志**：切到"调用日志"，展开一次运行，指出触发条件、每一步的角色和 token 用量、输入与返回、校验结果。

## 自动演示（带字幕）

- 点右上角"自动演示"：12 步自动走完收件箱 → 询盘回复 → 第 2 轮 → 看板 → 主图 → 上架 → 对照实验 → 红队 → 盲测成绩，每步有中文字幕和高亮框。
- 底部有"暂停 / 下一步 / 退出"，按 Esc 也能退出。
- 摊位循环播放：打开 `http://127.0.0.1:8765/#tour=loop`，走完自动从头开始。
- 建议用回放模式跑：实时模式下每一步都会真的调用模型，会慢，也会花额度。

## 游园会摊位

1. 笔记本和观众手机连同一个 Wi-Fi。
2. 运行 `cd app && TRADEDESK_MODE=replay python3 server.py --lan`，终端会打印手机访问地址。
3. 在大屏浏览器打开 `http://127.0.0.1:8765/play#screen`：左边是二维码，右边是每 3 秒刷新的排行榜。
4. 手机只能打开找茬页面；其他接口对手机一律返回 403，观众不会触发模型调用。
5. 开场前删除 `app/state/scores.json`，清空排行榜。

## 一键跳到演示状态

在浏览器地址后面加 `#demo=页面:序号:轮数:标签页:主题`，页面加载后会自动跑到指定状态（回放模式下不联网）：

| 地址 | 效果 |
|---|---|
| `http://127.0.0.1:8765/#demo=inquiry:0:1:reply:light` | 美国询盘第 1 轮，显示回复 |
| `http://127.0.0.1:8765/#demo=inquiry:0:2:diff:light` | 美国询盘第 2 轮，显示与第 1 轮的对比 |
| `http://127.0.0.1:8765/#demo=inquiry:1:2::light` | 墨西哥询盘（西语）第 2 轮 |
| `http://127.0.0.1:8765/#demo=listing:0:1::light` | 热水壶上架，Amazon + TikTok |
| `http://127.0.0.1:8765/#demo=check:0:1::light` | 文案体检，6 红 1 黄 |
| `http://127.0.0.1:8765/#demo=board::::light` | 商品看板 |
| `http://127.0.0.1:8765/#demo=inbox::::light` | 询盘收件箱 |
| `http://127.0.0.1:8765/#demo=inbox:1:::light` | 协同任务看板 |

| `http://127.0.0.1:8765/#demo=board:KET-17S:image` | 商品看板，并打开热水壶主图的检查结果 |

## 出问题时怎么恢复

| 现象 | 处理 |
|---|---|
| 状态栏显示红字、页面不动 | 服务没起来：终端里看报错，重新运行 `python3 server.py` |
| 点按钮后报"模型调用失败" | 网络或额度问题：Ctrl+C 停服务，用 `TRADEDESK_MODE=replay python3 server.py` 重启，按相同步骤再演示一遍 |
| 回放模式报"没有这条请求的缓存" | 输入和录制时不一样：重新点一下示例询盘卡片，不要手动改文字；修改意见只用"按风险提示全部修改"这个快捷建议 |
| 页面卡住超过 60 秒 | 刷新页面，改用回放模式 |
| 现场来不及手动操作 | 点右上角"自动演示"，讲解跟着字幕走 |
| 整台电脑出问题 | 播放备用录屏（**还没录**：赛前用 QuickTime 按"演示步骤"录一段，存为 `docs/demo-backup.mp4`） |
