03工作流 A · 询盘回复

先找出询盘和工厂资料对不上的地方，再用买家的语言如实回复：做不到的事，回复里写明做不到

1

理解

询盘分析员逐条抽取买家要求，每条带询盘原文，和资料卡比对标出硬冲突

2

生成

外贸业务员按阿里 RFQ 风格写英 / 西语回复，同时给内部写中文备忘、派任务

3

校验

代码比对价格、MOQ、交期、认证、付款、FOB；合规审核员按知识库审语义

4

反馈

原文高亮批注、红黄绿等级；一句中文“按风险提示全部修改”进入第 2 轮，逐词对比

05技术方案

代码负责数字和硬事实，模型负责语义判断；模型提出的问题如果没有规则编号或原文对不上，由代码直接丢弃

输入

用户

询盘原文、业务员意图、产品资料卡、主图

理解

询盘分析员

要求清单，每条带原文；没有出处的条目丢弃

生成

业务员 / 运营

按平台、语言、角色生成；注入规则摘要

校验

代码 + 合规审核员

代码规则 → 模型审核 → 出处守卫

反馈

界面

批注、红黄绿、逐词对比、任务

知识库38 条规则的摘要注入“生成”，原文供“校验”核对；资料卡字段供代码规则比对
① 代码规则价格、MOQ、交期、认证、付款、FOB、标题长度、禁用词：不让模型算数
② 模型审核合规审核员只拿到相关规则，必须给出规则编号并引用原文
③ 出处守卫编号不存在、原文里没有那句话 → 丢弃，界面显示丢了几条

Python 标准库服务端 + 原生 JS 前端，无需安装依赖 · 模型接口可换（OpenAI 兼容 / Claude）· 56 项自动化测试
